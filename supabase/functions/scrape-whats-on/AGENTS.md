# scrape-whats-on rules
- Event location filtering lives only in `supabase/functions/scrape-whats-on/locality.ts` (pure rules, regional feeds only: online → postcode district → competing area → own places → source named after a competing area → broad-source trust); left-out events are stored as status `excluded` with a reason, while owner-published events the rules now place elsewhere stay `published` with the reason kept as a Desk flag until the owner Keeps (`area_confirmed`, sticky by name, skips the rules) or Removes them; and owner removals/put-backs go through `set_topic_event_visibility` and stick by event name across the feed; one rule set keeps the feed, email and Sources list in agreement.
- Event photos are Curatr's own stored copies in `topic-assets/{topic}/events/` (never hotlinked), saved and deleted only by `scrape-whats-on` (`eventImage.ts` rules, `eventPhotos.ts` save/cleanup in the twice-daily gather: past, hidden, removed, changed, orphaned); cards show them via `eventPhotoUrl()` with the category illustration as fallback; one path keeps storage from growing.
