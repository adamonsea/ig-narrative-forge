- AI pictures are drawn automatically only once a story is live (`needsPublishIllustration` in `supabase/functions/_shared/illustration-gate.ts`, used by the writer, drip publisher and Desk Publish); drafts never cost credits. Owner "no picture" choices (`stories.skip_auto_illustration`, Autopilot pictures off via `feedAllowsAutoPictures`) are enforced inside `story-illustrator` for every automated call, so no path can bypass them.
- Story pinning: up to 9 live stories pinned at once on `stories.pinned_at`/`pinned_until`, set only via guarded `set_story_pin` (24/48/168h; hours 0 unpins that story) and listed publicly via `get_topic_pinned_stories` (fan deck above the feed); `set_story_pin` mirrors the most recent pin into `topics.pinned_story_id` so feed RPCs, emails and `storyPin.ts` rules keep one leading story with no clean-up job.
- Publisher names only in `publisherNames.ts`; site address/sender only in `brandConfig.ts` (email, RSS, widget, push); modules never hard-code brand or tenant values, so they stay liftable.
- Website widgets pick news, events or both only via `resolveWidgetContent` and look (`data-style` list = headlines with News | What's on tabs, cards = swipeable feed-style cards, both = one row ordered by `mixWidgetCards`) only via `_shared/widgetContent.ts` (auto = events-led feeds show events, others keep news; events only when shown in the feed); builders preview through `LiveWidgetPreview` running the real `widget.js` (`data-preview` = not counted), so preview, embed and tests never drift.
- RSS enclosures carry only Curatr illustrations (`illustration_generated_at` set, our storage, not `publisher-N`); uncredited source photos never leave via RSS.
- Every AI action meters through `allowance.ts` (`meterUsage` → `usage_events`, `logApiUsage` → `api_usage` with payer + feed): system calls (service-role key) bill the feed owner and never bypass; charging only when the `billing_enforce` flag is on (otherwise shadow rows); `user_credits.billing_exempt` accounts are metered, never charged; one meter keeps shadow figures and real charges identical.
- Scheduler gates use `automationGate` (skip, never fail) backed by SQL `automation_pause_reason`/`billing_owner_status`; Desk, Usage and gates read the same SQL, and every new limit (free feed count, Pro-only API/handle, welcome checks) is inert until `billing_enforced_for(owner)` is true (global flag, or `user_credits.billing_enforce_test` for a single test account).
- Picture variety (shot type and casting for people the story doesn't identify) comes only from `pictureVariety.ts`, seeded by story id and fed to both the scene writer and the artist prompt; one picker keeps runs of stories varied while a regenerate keeps its brief.
- Edge functions acting on one feed gate with `requireTopicManager` (service role, or the feed owner/admin) from `_shared/auth.ts`; untargeted scheduled runs stay open, requests naming a feed/story never are; keeps tenants apart.
- Picture jobs are single-flight per story via service-only `claim_story_illustration`/`release_story_illustration` (10-min expiry; automated jobs never redraw an existing picture) and the credit key uses the claim id; a second job skips before any charge.
- Server-side fetches of user-supplied links go through `fetchPublicHtml`/`isPublicHttpUrl` in `_shared/safeUrl.ts` (private/metadata addresses blocked, redirects re-checked); stops requests reaching internal hosts.
- Curated illustration colour sets live only in `illustrationColourSets.ts` (re-exported in `src/lib`); a picture uses one whole set, never mixed (`colourSetRule` appended to the prompt). Picture colours "Sets" saves `illustration_color_mode` 'random' (any whole set) or 'set' + `illustration_color_set`; one list keeps Settings and the illustrator in agreement.
