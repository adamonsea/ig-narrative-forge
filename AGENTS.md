# Project Architecture Rules

- Render the Curatr identity through `src/components/brand/CuratrLogo.tsx`; one shared lock-up keeps the icon and `.pro` proportions consistent.
- Reuse `public/reveal.html` for explainer-film ident scenes and deterministic video exports (`?clean=1&capture=1`, `window.__curatr.frame(t)` after fonts load); one reveal source keeps the animated mark and wordmark balanced everywhere.
- All reader numbers (reading now via `topic_reading_now`, readers, reads, per-story, returning) come only from `topic_engagement` signals (swipe, 3s+ stop, 10s+ story page) via `topic_reads`/`count_topic_readers`; Visits only from `count_topic_visitors`; one list keeps figures in agreement.
- Google Search figures come only from `search_daily` (system-only, filled daily by `search-console-sync`), counting only days 3+ days old; half-reported days never look like drops.
- Client-callable SECURITY DEFINER functions start with a guard (`can_view_topic_stats`/`can_view_user_stats`, or `can_manage_topic` for feed actions); jobs are service-role only; keeps tenants apart.
- The /dashboard feed card reads all its figures from the single `get_dashboard_feed_cards` call; one guarded query keeps the card fast and tenant-safe.
- Feed-card highlights and nudges are picked by pure rules in `src/lib/feedHighlights.ts` from the single card call (no AI); keeps every positive true and testable.
- Reader trackers and GA obey only `readerTrackingMode()` (`src/lib/readerConsent.ts`, regional rules; modes full / anonymous = UK 7-day ID / visit = in-memory only / off; IDs from `getVisitorId`) via `canTrackReader`/`getVisitorId`/`onReaderTrackable` in `visitorIdentity.ts`, after a human signal; one gate keeps regions consistent and bots out.
- Reaction identities must preserve an existing `curatr_visitor_id` verbatim; stored anonymous reactions use exact ID matching, while new readers use the shared visitor identity.
- Headline stop data is written only via the `record_story_views` batch RPC (insert or upgrade seen→paused, today only), from an IntersectionObserver-only tracker that sends on pagehide/hide; keeps the feed fast and rows tamper-safe.
- Reader-facing feed filtering (Curate menu, More like this, filter banner, filter index download) is gated by `FEED_FILTERS_ENABLED` in `src/lib/featureFlags.ts`; one switch pauses or restores it without touching topic keyword data.
- Reader first-visit extras on public feeds (welcome card/tooltip tour, pulses, in-feed install card, auto notification pop-up, multi-step end-of-feed flow) are gated by `READER_ONBOARDING_EXTRAS` in `src/lib/featureFlags.ts`; curator settings are kept but ignored while it's off, so one line restores them.
- Never delete production reader data (story_impressions, story_interactions, site_visits, feed_visits) by time window or topic. Test browsers must use a visitor_id prefixed zztest_ (set in localStorage before load; `is_test_visitor` keeps it out of every figure) and cleanup may only delete that exact visitor_id. Reader numbers are never padded or adjusted for display.
- Never create test accounts or trigger auth emails to made-up or non-existent addresses (e.g. tenant-test-b@curatr.pro); it caused a Supabase bounce-rate warning on 5 Nov 2026. Test tenant isolation via SQL with simulated JWT claims, or ask the owner for a real test inbox.
- Tenant Readership figures come only from the guarded `get_topic_readership` (same reads definition as the dashboard card); the Desk shows only `get_topic_pulse` figures, and the funnel appears only above `MEANINGFUL_READERS` weekly readers.
- Engagement figures (returning, per-story, sent to sources, per visit, sign-ups) come only from guarded `get_topic_readership` with `topic_engagement` exclusions; capture via `record_story_interaction`/`record_event_click` (kind) behind `canTrackReader()`; picks in `readerStats.ts`; one honest source.
- Every per-story attention score (Readership top stopper and stopped/swiped line, card highlight, widget Most read, any future boost) comes only from `story_stop_scores` (position-corrected stop rate; a stop = 3s+ continuous dwell from `max_dwell_ms`, never `paused`; swipe rate uses the same impression rows; `STORY_SCORE_FLOOR` outside readers), revoked from app roles; one definition and floor everywhere.
- The Desk pulse (reading now = last 5 min, per-story 7-day reads, rising = most reads in 3h, new arrivals since last look, milestones) comes only from the guarded `get_topic_pulse`, polled every 30s; "last looked" and milestone dismissals live in `curator_topic_state` per account so devices agree.
- The public feed pages 20 stories at a time: both `get_topic_stories_with_keywords` and `get_public_topic_feed` limit by story and sort by display date then id, and each next page starts 2 stories before what's loaded (de-duplicated by id); this keeps pages in true feed order with no gaps, no repeats and correct card positions.
- Public-feed extras (sentiment, quiz, insights, flashback, parliament, events, pulse) show only when that feed's own settings switch them on, all off by default; parliament/events have feed-only switches so data collection and the weekly email are unaffected.
- Reader-facing cards that use a feed's colour must get it from `feedBrandPalette()` (`_shared/feedBrandColor.ts`, re-exported in `src/lib`; emails too); one helper keeps feed colours readable.
- In-feed card placement lives only in `src/lib/feedCardPositions.ts` (single, repeating, or leading-then-repeating "sequence" rules, covered by tests); one registry prevents collisions and silent position drift.
- Reader-facing slide lists come from `prepareStorySlides()` in `src/lib/lastSlide.ts` (Source: credits and reader prompts hidden with appeal/detail protections, empty closing slides dropped, "By {reporter}" byline), used by the feed card and the social pack export; it runs at render and never rewrites stored copy, so rules can change without touching data.
- Story slides 2+ share one fit-to-card font size per story from `useStoryFontSize` in `src/lib/slideTextFit.ts`, and the rendered text and off-screen measurer both use its `FIT_TEXT_CLASS`/`FIT_TEXT_STYLE`; one measured size avoids jumps, and one style source stops measuring drift that would clip text.
- Home and landing-page animations embed the explainer's own scene components through `src/components/home/HomeSceneLoop.tsx` (scaled virtual stage, mounted in view, looped by remount); audience wording via optional `SceneContentContext` falling back to the explainer's copy, so one scene source serves every page.
- The shared global story categories are a local-news set and apply only to regional feeds (`usesGlobalTaxonomy` in `supabase/functions/_shared/taxonomy.ts`, mirrored in `useStoryCategories`); other feeds use only their own categories, added from "Suggest categories", so subject feeds never get courts/council sections.
- Audience landing pages (/for/...) render through `src/components/landing/AudienceLanding.tsx` with copy in `audienceConfigs.ts`; they copy the home page patterns instead of sharing them, so landing-page edits never touch the home page.
- Feed events: Grouped reads `get_topic_whats_on` → `whatsOnSets()` at `whatsOnPositions()`; Individual (events-led default) pages `get_topic_events_feed` 20 at a time like news, and events-led order is `eventsLedRun()` (news by `NEWS_IN_EVENTS`, extras counted in events). Categories: `_shared/eventCategories.ts` rules at gather, leftover Other gets one background model check (`categoryCheck.ts`), owner `category_locked` wins; prices via `_shared/currency.ts`. One rule set for feed, Desk, tests.
- Sources only says where things come from (news and events sources in one list, kind detected from the link, per-source Auto-publish); everything that comes through is managed on the Desk (news in the Story pool, events in the Event pool, waiting ones pinned for one-click OK, both into Live now; Hidden group, Events switch and "Show in the feed"); events land via `placeEvent()` in `scrape-whats-on/relevance.ts` (news scorer + location rules; out of area → Hidden, low relevance never auto-publishes).
- Briefing events come only from `_shared/briefingEvents.ts` (pages via `useBriefingEvents`, weekly email): look ahead from today, current briefings only, never stored in roundups.
- Readers never write `topic_newsletter_signups` directly: email via `secure-newsletter-signup`, browser notifications via `save-push-subscription` (owner/service-only table).
- Event clicks: written only via `record_event_click` (`canTrackReader()`, owner clicks skipped), read only via `get_topic_readership`; tenant-safe.
- Parked features are switched off only via `FEATURES` in `supabase/functions/_shared/parked-features.ts` (shared with the app via `featureFlags.ts`): screens hide and jobs return early, never by editing feeds' saved values; see docs/parked-features.md.
- Feed Settings is one page in `EditorialControlCenter.tsx`: basics per section, every control one tap away in a per-owner `RememberedFold`; old `?section=` links open the matching fold.
- New feeds start from one sentence (`suggest-feed-setup` rules + `src/lib/feedSetup.ts`); fandom feeds set `brand_safe_pictures` (no drawn characters/logos). Feed terms are edited only in `LookForPanel` via `src/lib/termLists.ts` (case-insensitive, one list per term).
- Autopilot = automation_mode 'holiday' + `auto_simplify_enabled=true`; turning it off never clears that flag (hand-written stories use it).
- Desk story cards use `DeskCard` (quiet, ≤2 actions, drawer for more).
- Editing opens in `WorkspaceDrawer` (src/components/workspace); deletes use confirm boxes; errors `InlineError`.
- Marketing colours: `shop-*` tokens only.
- Admin-only `/design` (`pages/design/DesignSystem.tsx`) is the workspace system; add new UI there first.
- Events|All|News switch only via `showFeedViewToggle`; display-only.
- Source photos always credited (photoCredit.ts), use_publisher_photos off=none new
- Feed top bar/background: owners pick only those two; all colours on them come from `feedSurfaces.ts`, shared by feed and Settings Look preview; keeps both identical and readable.
- Event editorial copy is generic: per-feed `feed_editorial_profiles`, text in `event_copy` (event × language × kind), captions in `event_captions`, hand-edit locks in `event_field_edits`; captions are assembled by code in `src/lib/editorial/captionAssembler.ts`, AI never writes facts; any feed can use it without feed-specific columns.
