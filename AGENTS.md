# Project Architecture Rules

- Render the Curatr identity through `src/components/brand/CuratrLogo.tsx`; one shared lock-up keeps the icon and `.pro` proportions consistent.
- Reuse `public/reveal.html` for explainer-film ident scenes and deterministic video exports (`?clean=1&capture=1`, `window.__curatr.frame(t)` after fonts load); one reveal source keeps the animated mark and wordmark balanced everywhere.
- Dashboard visitor figures come only from `count_topic_visitors` (distinct external browser codes, prefix-stripped, across site_visits/story_interactions/story_impressions/feed_visits); one definition keeps every screen in agreement.
- Google Search figures come only from `search_daily` (system-only, filled daily by `search-console-sync`), counting only days 3+ days old; half-reported days never look like drops.
- Every SECURITY DEFINER stats function must start with `can_view_topic_stats` / `can_view_user_stats` and return nothing otherwise; this keeps tenants from reading each other's analytics.
- The /dashboard feed card reads all its figures from the single `get_dashboard_feed_cards` call; one guarded query keeps the card fast and tenant-safe.
- Feed-card highlights and nudges are picked by pure rules in `src/lib/feedHighlights.ts` from the single card call (no AI); keeps every positive true and testable.
- Every reader tracker (and GA) must pass `canTrackReader()` in `src/lib/visitorIdentity.ts` (not a bot, not "Essential only"); one gate keeps consent consistent.
- Reaction identities must preserve an existing `curatr_visitor_id` verbatim; stored anonymous reactions use exact ID matching, while new readers use the shared visitor identity.
- Headline stop data is written only via the `record_story_views` batch RPC (insert or upgrade seen→paused, today only), from an IntersectionObserver-only tracker that sends on pagehide/hide; keeps the feed fast and rows tamper-safe.
- Reader-facing feed filtering (Curate menu, More like this, filter banner, filter index download) is gated by `FEED_FILTERS_ENABLED` in `src/lib/featureFlags.ts`; one switch pauses or restores it without touching topic keyword data.
- Reader first-visit extras on public feeds (welcome card/tooltip tour, pulses, in-feed install card, auto notification pop-up, multi-step end-of-feed flow) are gated by `READER_ONBOARDING_EXTRAS` in `src/lib/featureFlags.ts`; curator settings are kept but ignored while it's off, so one line restores them.
- Never delete production reader data (story_impressions, story_interactions, site_visits, feed_visits) by time window or topic. Test browsers must use a visitor_id prefixed zztest_ (set in localStorage before load) and cleanup may only delete that exact visitor_id.
- Never create test accounts or trigger auth emails to made-up or non-existent addresses (e.g. tenant-test-b@curatr.pro); it caused a Supabase bounce-rate warning on 5 Nov 2026. Test tenant isolation via SQL with simulated JWT claims, or ask the owner for a real test inbox.
- Tenant Readership figures come only from the guarded `get_topic_readership` (same reads definition as the dashboard card); the Desk shows no stats, and the funnel appears only above `MEANINGFUL_READERS` weekly readers.
- Every per-story attention score (Readership top stopper and stopped/swiped line, dashboard card highlight, widget Most read shelf, any future boost) comes only from `story_stop_scores` (its swipe rate shares the same impression rows as the stop rate) (position-corrected stop rate where a stop is 3s+ continuous dwell derived from `max_dwell_ms`, never the stored `paused` flag; `STORY_SCORE_FLOOR` distinct outside readers); it is revoked from app roles and called only by guarded functions, so one definition and one floor apply everywhere.
- The Desk pulse (reading now = last 5 min, per-story 7-day reads, rising = most reads in 3h, new arrivals since last look, milestones) comes only from the guarded `get_topic_pulse`, polled every 30s; "last looked" and milestone dismissals live in `curator_topic_state` per account so devices agree.
- The public feed pages 20 stories at a time: both `get_topic_stories_with_keywords` and `get_public_topic_feed` limit by story and sort by display date then id, and each next page starts 2 stories before what's loaded (de-duplicated by id); this keeps pages in true feed order with no gaps, no repeats and correct card positions.
- Public-feed extras (sentiment, quiz, insights, flashback, parliament, events, pulse) show only when that feed's own settings switch them on, all off by default; parliament/events have feed-only switches so data collection and the weekly email are unaffected.
- Reader-facing cards that use a feed's colour must get it from `feedBrandPalette()` in `src/lib/feedBrandColor.ts` (contrast-corrected for the feed card in light and dark mode); one helper keeps every feed's colours readable whatever the curator picks.
- In-feed card placement lives only in `src/lib/feedCardPositions.ts` (single, repeating, or leading-then-repeating "sequence" rules, covered by tests); one registry prevents collisions and silent position drift.
- Reader-facing slide lists come from `prepareStorySlides()` in `src/lib/lastSlide.ts` (Source: credits and reader prompts hidden with appeal/detail protections, empty closing slides dropped, "By {reporter}" byline), used by the feed card and the social pack export; it runs at render and never rewrites stored copy, so rules can change without touching data.
- Story slides 2+ share one fit-to-card font size per story from `useStoryFontSize` in `src/lib/slideTextFit.ts`, and the rendered text and off-screen measurer both use its `FIT_TEXT_CLASS`/`FIT_TEXT_STYLE`; one measured size avoids jumps, and one style source stops measuring drift that would clip text.
- Home and landing-page animations embed the explainer's own scene components through `src/components/home/HomeSceneLoop.tsx` (window-sized virtual stage scaled into the frame, mounted only in view, looped by remount); audience wording is passed via the optional `SceneContentContext` that falls back to the explainer's copy, so one scene source serves every page without changing the film.
- The shared global story categories are a local-news set and apply only to regional feeds (`usesGlobalTaxonomy` in `supabase/functions/_shared/taxonomy.ts`, mirrored in `useStoryCategories`); other feeds use only their own categories, added from "Suggest categories", so subject feeds never get courts/council sections.
- Audience landing pages (/for/...) render through `src/components/landing/AudienceLanding.tsx` with copy in `audienceConfigs.ts`; they copy the home page patterns instead of sharing them, so landing-page edits never touch the home page.
- Every events source lives in `event_sources` with a `kind`, read only through `scrape-whats-on` by the reader registered for that kind (`readers/index.ts`; pasted addresses auto-detected; `whats_on_page` = JSON-LD → iCal/JSON feed → text kept only when title and date text appear together, dates parsed by rules in `extract.ts`, never by the model; `calendar_feed` = Chamber-style JSON); events link back via `event_source_id` and what's-on removals stay sticky; a new kind is one reader, never a redesign.
- Event location filtering lives only in `supabase/functions/scrape-whats-on/locality.ts` (pure rules, regional feeds only: online → postcode district → competing area → own places → broad-source trust); left-out events are stored as status `excluded` with a reason, and owner removals/put-backs go through `set_topic_event_visibility` and stick by event name across the feed; one rule set keeps the feed, email and Sources list in agreement.
- The feed reads events only via `get_topic_whats_on` (one row per event name, next 31 days, same-day events hidden once started or after 18:00 if untimed) and rotates up to three `WhatsOnCard` sets from `whatsOnSets()` in `src/lib/whatsOn.ts` (Today / This week / Later this month, empty sets skipped, up to `WHATS_ON_MAX` each) at `whatsOnPositions()`; event links for the next two days are checked on each refresh and fall back to the source page when gone. One rule set keeps feed, Desk and tests in agreement.
- Sources only says where things come from (news and events sources in one list, kind detected from the link, per-source Auto-publish); everything that comes through is managed on the Desk (stories and events in one Waiting → Live pipeline, Hidden group, Events switch and "Show in the feed"); events land via `placeEvent()` in `scrape-whats-on/relevance.ts` (news scorer + location rules; out of area → Hidden, low relevance never auto-publishes). One rule keeps each place doing one job.
- Event link clicks are written only via the `record_event_click` RPC (gated by `canTrackReader()`, owner clicks skipped) and read only through `get_topic_readership`; keeps venue-click figures tenant-safe and consistent.
- Clickable product mocks live under `src/pages/dashboard/mock/`, lazy-loaded behind a superadmin/product-owner guard, with dummy data kept only in the browser; they never read or write real feeds, so ideas can be tested without touching the live Desk or feed.
